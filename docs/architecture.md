# 实现结构

最终结果始终从输入的 ZIP 部件生成。整个流程不调用 openpyxl，也不将 Excel 保存的工作簿当作最终交付。

```mermaid
flowchart LR
    A[输入 XLSX 与完整操作列表] --> B[包与目标预检]
    B --> C[原 XML 字节片段注入]
    C --> D[隔离 Excel 临时副本]
    D --> E[公式与图表系列交叉核验]
    E --> F[缓存片段回填原包]
    F --> G[图片增量注入]
    G --> H[补丁重放与关系检查]
    H --> I[原子发布新输出和报告]
```

没有计算依赖和图片操作的文字/数值修改会跳过 Excel。图片尺寸由 Excel 的 Range/Shape 属性提供；外部连接只在临时副本中禁用自动刷新。计算过程中不调用 RefreshAll，不更新外部链接，只刷新本地工作表来源的透视缓存。

## 模块

| 文件 | 职责 |
| --- | --- |
| `server.py` / `models.py` | SDK stdio 接入、类型化工具、结构化与文本输出、业务错误 |
| `xmlbytes.py` | Expat 命名空间定位、原字节偏移、属性编辑、片段替换、补丁记录 |
| `package.py` | ZIP 原部件、哈希、关系、内容类型、新部件与发布前验证 |
| `workbook.py` / `strings.py` | 工作表与名称作用域、静态范围、样式、富文本、图表/图片/透视索引、Xstring 转义 |
| `cells.py` | 操作冲突、合并区域、标量/矩阵、现有样式引用、单元格与 dimension 局部注入 |
| `images.py` | 图片预检、共享媒体保护、比例适配、锚点保留与 drawing 增量追加 |
| `excel_worker.py` / `calculation.py` | 独立 COM 进程、计算、固定布局透视刷新、缓存语义映射与回填 |
| `integrity.py` | 独立补丁重放、完整部件比较、关系 ID 与缓存结构核验 |
| `engine.py` | 整批流程、源文件变化检测、新文件发布与失败回滚 |
| `runtime.py` | 平台能力、Windows Excel 注册状态、需计算操作的提前拒绝 |
| `reports.py` / `report_data.py` / `report_plots.py` | 已确认的来源/模板映射、原 CSV 独立统计、静态 PNG 和离线报告注入 |
| `report_objects.py` | 精确删除映射的示例图对象，清理其不再共享的关系与依赖部件 |
| `report_styles.py` | 独立核验报告保留原样式、字体及行列格式 |
| `report_template.py` | 明确执行的极片母版制作：新原生表格、参考图框和准备审计 |

源码与 XML 引擎在 Windows/macOS 共用；`pywin32` 用平台依赖标记限定为 Windows。`scripts/setup.py` 在目标路径创建虚拟环境，执行 SDK stdio 自检，再生成绝对 command/args；POSIX 解释器路径不解析软链接，以保留虚拟环境。Mac 本版支持无计算依赖的 XML 操作；不提供 Excel for Mac 后端。计算依赖当前按整个工作簿判断。

锁文件还按 `platform_machine` 为 Intel macOS 选择 cryptography 48.0.1，其他平台选择 50.0.2；前者提供 universal2 wheel，后者的 macOS wheel 只支持 arm64。MCP 的运行依赖范围接受两者。[上游变更记录](https://github.com/pyca/cryptography/blob/main/CHANGELOG.rst)

## 字节与计算保证

报告保存输入/输出文件指纹、每个部件的 SHA-256 和有顺序的补丁阶段。每条补丁记录旧片段位置、旧片段哈希、新字节、修改原因及目标标识。验证器从原文件重放补丁并与实际输出逐字节比较；未在补丁内的字节必须相同。ZIP 压缩后的容器字节不作为一致性指标。

修改范围由操作目标和适配器限定，不能授权整部件任意重写。已有图表缓存同索引的数据点只更新值；缓存扩展和数据点元数据保留。改变点集合时若涉及无法保留的点元数据，会拒绝。透视缓存只回填已支持的共享项目、记录和固定结果网格；其他配置无法保持时拒绝。

计算副本按工作表/单元格、图表对象名称/来源表达式、透视表名称/字段/结果范围映射。图表缓存还与 Excel COM 的系列值、分类值和名称比较。显式写入的值必须在计算副本中保持一致，避免控件关联或派生网格覆盖输入后误交付。

完整性报告属于可检查的修改记录，不是签名或独立可信意图证明。验证器检查其与两个工作簿是否一致；用户修改工作簿和报告后，需要另外审查修改意图。

## 失败与进程清理

输出及报告不得已经存在。暂存文件位于输出目录的本次临时子目录中；全部检查通过才发布。Windows rename 提供单个文件不覆盖发布；POSIX 使用同目录硬链接后移除暂存文件，目标存在时失败。两个文件不组成操作系统事务，若第二次发布失败，只撤回本次成功发布的报告，保留其他进程创建的文件。

Excel 进程由 DispatchEx 创建，PID 必须未出现在启动前的进程清单中。拥有记录同时保存 PID 与进程创建时间；超时或退出清理只处理身份仍匹配的本次进程。失败不发布 XLSX；业务错误通过 MCP `isError` 返回，诊断日志仅写 stderr。
